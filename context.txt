 0. HOW TO ACTIVATE GPU (READ THIS FIRST)
================================================================================

GPU training needs TWO things:
  (1) NVIDIA driver working          -> nvidia-smi shows your GPU
  (2) PyTorch CUDA wheel installed   -> NOT the default CPU-only pip torch

The project config alone does NOT activate GPU. You must install CUDA PyTorch
and START A NEW training process after that.

--- ACTIVATION CHECKLIST (do in order) ---

  1. Check NVIDIA driver (does NOT install anything):
       nvidia-smi
     Expected: GPU name + driver version (e.g. RTX A2000, driver 595.x)

  2. Install project Python deps:
       pip install -r requirements.txt

  3. Check current PyTorch:
       python scripts/check_gpu.py

     BAD (CPU-only — GPU NOT active for training):
       PyTorch version : 2.12.0+cpu
       CUDA available  : False

     GOOD (GPU active for PyTorch):
       PyTorch version : 2.12.0+cu126   (or +cu124, +cu128)
       CUDA available  : True
       Matmul smoke OK : ... on cuda:0

  4. If step 3 failed — install CUDA PyTorch (ONLY changes the torch package):

       pip install --force-reinstall torch --index-url https://download.pytorch.org/whl/cu126

     On another PC, pick cu124 / cu126 / cu128 from:
       https://pytorch.org/get-started/locally/

     WARNING: Do NOT use plain "pip install torch" — it often installs CPU-only.
     Do NOT uninstall or change NVIDIA drivers with pip.

  5. Re-run check until it passes:
       python scripts/check_gpu.py

  6. Config already has device: cuda in configs/curriculum_hanif.yaml.
     Start training (NEW process — stop any old run first with Ctrl+C):

       python main_train.py --config configs/curriculum_hanif.yaml --curriculum

  7. CONFIRM in the FIRST log line of training:

       GOOD:  Curriculum training on device: cuda — NVIDIA RTX A2000 12GB (12.0 GB)
       BAD:   Curriculum training on device: cpu

     If you see "cpu", the running process started before CUDA PyTorch was
     installed — stop it and restart from step 6.

  8. Optional — watch GPU usage while training (second terminal):
       nvidia-smi -l 2
     GPU-Util and memory should increase during training steps.

Multi-Agent Reinforcement Learning solver for E-VRPTW (Electric Vehicle
Routing Problem with Time Windows and Recharging Stations).

Architecture:
  - Transformer encoder over full static graph (depot + customers + stations)
  - Event-driven asynchronous multi-EV decoder
  - Hard feasibility masks (battery, capacity, TW, anti-stranding, reservations)
  - Partial charging at stations with Hanif log-normal energy prices
  - REINFORCE training + progressive curriculum over instance classes C, R, RC
  - Fleet-size search at validation/evaluation time

Primary benchmark: Hanif EVRPTW variant B (relaxed time windows), 1000 customers
per instance, ~333 charging stations, battery 600, per-instance load capacity
(200 / 700 / 1000 depending on series).

 4. GPU DETAILS (EXPANDED — see section 0 for activation checklist)
================================================================================

IMPORTANT: GPU training uses PyTorch CUDA wheel — NOT the NVIDIA driver alone.
Your driver can be fine while PyTorch still runs on CPU (2.12.0+cpu).

Symptoms you are NOT on GPU:
  - Log says: "Curriculum training on device: cpu"
  - check_gpu.py shows CUDA available: False
  - ~45–90 seconds per Hanif training iteration

Symptoms you ARE on GPU:
  - Log says: "Curriculum training on device: cuda — <GPU name> (... GB)"
  - check_gpu.py passes with Matmul smoke OK on cuda:0
  - nvidia-smi shows python.exe using GPU memory during training

--- Step A: Verify NVIDIA driver (any PC with NVIDIA GPU) ---

  nvidia-smi

  You should see your GPU name and driver version. If this fails, install/update
  NVIDIA drivers first (from nvidia.com) — do NOT use pip for drivers.

--- Step B: Install Python deps ---

  cd Transformer_MARL_EVRP
  pip install -r requirements.txt

--- Step C: Install PyTorch WITH CUDA (critical step) ---

  First check what you have:

    python scripts/check_gpu.py

  If it says "2.12.0+cpu" or CUDA available: False, install CUDA PyTorch.

  This PC (RTX A2000, driver 595.71) uses cu126 successfully:

    pip install --force-reinstall torch --index-url https://download.pytorch.org/whl/cu126

  Other PCs — pick wheel matching driver (see pytorch.org/get-started/locally):
    cu124  -> older CUDA 12.4 builds
    cu126  -> CUDA 12.6 (recommended if driver supports CUDA 12.x+)
    cu128  -> newer builds if available

  NOTE: pip install torch (default PyPI) often installs CPU-only on Windows.
  Always use the --index-url line above for GPU training.

--- Step D: Confirm GPU works ---

    python scripts/check_gpu.py

  Expected output on this PC:
    PyTorch version : 2.12.0+cu126
    CUDA available  : True
    GPU 0: NVIDIA RTX A2000 12GB (12.0 GB)
    Training device : cuda — NVIDIA RTX A2000 12GB (12.0 GB)
    Matmul smoke OK : ...

--- Step E: Train on GPU ---

  STOP any old training first (Ctrl+C) if it was started on CPU.

  Config already has device: cuda. Run:

    python scripts/convert_hanif_dataset.py          # once per machine
    python main_train.py --config configs/curriculum_hanif.yaml --curriculum

  At startup you MUST see (first INFO line):

    Curriculum training on device: cuda — NVIDIA ... (... GB)

  If you see "device: cpu", PyTorch CUDA is still not installed — redo Step C
  and start a NEW training process (do not continue an old one).

  Optional CLI override:

    python main_train.py --config configs/curriculum_hanif.yaml --curriculum --device cuda

  Force CPU (debug only):

    python main_train.py --config configs/curriculum_hanif.yaml --curriculum --device cpu

--- Step F: Dashboard (second terminal) ---

    python main_dashboard.py --config configs/curriculum_hanif.yaml
    -> http://localhost:8080

--- Performance expectations ---

  CPU (2.12.0+cpu):  ~45–90 seconds per training iteration on Hanif 1000-customer
  GPU (RTX A2000):   typically several times faster (exact speed varies)

  If training was started BEFORE installing CUDA PyTorch, stop it (Ctrl+C) and
  restart — old process still uses CPU.

 8. TROUBLESHOOTING
================================================================================

  Training says "device: cpu"
    -> PyTorch is CPU-only wheel. Run check_gpu.py and reinstall cu126 torch.

  "device=cuda requested but PyTorch cannot use CUDA"
    -> Same fix as above.

  Port 8080 busy (dashboard)
    -> python main_dashboard.py --config configs/curriculum_hanif.yaml --port 8081
